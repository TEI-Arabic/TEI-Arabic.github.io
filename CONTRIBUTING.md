# Contributing to TEI-Arabic

This guide and the accompanying templates are proposed on the audit branch for curator review. They do not change repository permissions.

Contributions in Arabic or English are welcome. A contributor does not need to translate their own submission: request help with the other language before publication.

## A small, reviewable change

Use GitHub's Edit File interface on a working branch, or work in a local clone. Start from the latest main, change the relevant files, and inspect the diff. For this audit, propose changes through a pull request instead of editing the published main branch. The curators can agree on the ongoing workflow separately.

Keep content corrections separate from new sections, branding decisions, and permission changes. Do not undo another contributor's edits merely because they differ from an older copy.

## Projects

Edit matching project sections in `projects.html` and `projects-ar.html`. Retain the same stable section ID in both. Provide a title, contributor/team, languages and scripts, source material, a short description, TEI use or proposed use, and public links. Distinguish an existing TEI implementation from an experiment or future plan. Ask the project owner to verify substantive changes. Do not present membership, funding, or an affiliation as an endorsement of the whole forum.

## Resources

Use the relevant category in both resource pages. Give the title, URL, a short purpose statement, and any relevant version/platform limits. Preserve attribution. A failed automated fetch is not proof that a link is broken. Check legacy instructions before recommending them as a current workflow.

## Members and contact information

Ask a curator before changing membership or public contact details. A contact address in an internal sign-up sheet is not, by itself, evidence of permission to publish it. Obtain confirmation for new public details. Do not paste private correspondence, consent records, meeting links, or unpublished research into a public issue or pull request. Existing contacts have not been independently re-authorized by this audit.

## Before review

Check both languages, headings, internal links, project IDs, and the language switch. Test keyboard navigation and small screens. Cite sources for substantive factual changes and record anything that remains unverified. Keep schema validity separate from the scholarly adequacy of an encoding.

## بالعربية

نرحب بالمساهمات بالعربية أو الإنجليزية، ويمكن طلب المساعدة في إعداد النسخة الأخرى. عدّلوا نسخة العمل لا الموقع المنشور أثناء هذه المراجعة، وراجعوا الفرق بين النسختين قبل اقتراح دمج التعديل. حافظوا على معرّف المشروع نفسه في الصفحتين، وميّزوا بين استخدام قائم لمعيار TEI وخطة مستقبلية. لا تُنشر بيانات اتصال جديدة أو مواد غير منشورة دون التأكد من الإذن. هذه الإرشادات مقترحة للمراجعة، ولا تغيّر صلاحيات الأعضاء.
